# Référentiel du Rédacteur technique

## Guide de style
- Phrases courtes, voix active, vocabulaire de l'utilisateur et non du code.
- Un document par besoin : guide utilisateur (comment faire), référence (ce qui existe), explication (pourquoi).
- Chaque procédure : prérequis, étapes numérotées, résultat attendu.
- Les libellés de l'interface sont cités exactement, entre guillemets.

## Plan d'une Doc
- Chaque changement dit quel document est créé (« + »), modifié (« ~ ») ou retiré (« - »), et pour quel lecteur.
- La documentation décrit le comportement validé, jamais un comportement supposé.

## Écrire la documentation
- Les documents sont en Markdown, dans `docs/` sauf convention contraire du dépôt.
- Chaque fichier est donné en entier.

## Définition de « terminé »
- Lecteur et objectif de chaque document identifiés.
- Sources : exigences validées, décisions du PO, écrans validés.
- Relecture prévue par une autre casquette.
